# Publishing

Repo: https://github.com/Digidai/metix-reports

## Enable GitHub Pages

1. Settings → Pages → Source: **GitHub Actions**
2. Workflow `.github/workflows/pages.yml` deploys `docs/`
3. Expected URL: https://digidai.github.io/metix-reports/

## Custom domain (optional later)

Add `docs/CNAME` with e.g. `reports-catalog.metix.ai` and configure DNS + Pages custom domain. Keep canonical report URLs on `metix.ai`.

## Refresh catalog

Triggers on `.github/workflows/sync-catalog.yml`:

- schedule: `17 6 * * *` every day, plus `7 1 * * 1-5` (about 01:07 UTC on weekdays, after the Asia/Shanghai morning publish window)
- `workflow_dispatch`
- `repository_dispatch` with `event_type` `metix-catalog-sync` (Digidai/openjobs-reports can POST this right after deploy)

The dispatch token needs permission to create a repository dispatch on this repo (`contents: write` on a fine-grained token, or classic `repo`). Example:

```bash
curl -sS -X POST \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $METIX_REPORTS_DISPATCH_TOKEN" \
  https://api.github.com/repos/Digidai/metix-reports/dispatches \
  -d '{"event_type":"metix-catalog-sync"}'
```

Local refresh:

```bash
node scripts/sync-catalog.mjs
git add data/catalog.json README.md docs/index.html docs/llms.txt
git commit -m "chore: sync catalog from metix sitemaps"
git push
```

`docs/llms.txt` is regenerated by the same script. It lists the canonical LLM indexes and hubs, plus title and URL lines from the catalog. It does not copy report bodies. Pages deploys `docs/` on push to `main`, and again after a successful catalog sync (`workflow_run`), because a `GITHUB_TOKEN` push does not start `on: push` workflows.
